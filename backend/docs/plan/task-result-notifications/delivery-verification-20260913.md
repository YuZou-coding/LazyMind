## 修复后的行为

飞书 SDK 明确拒绝且不可自动重试时，通知分片记录安全码 `FEISHU_SEND_REJECTED`，不再当作首次请求响应丢失。被拒绝的文件记录 failed，事务内保存包含文件名及 LazyMind 查看提示的说明卡，继续发送其余文件；整体可显示 partial。后续分片暂时失败引起整条队列再次调度时，也不会自动重发已经明确被拒绝的分片。

人工重试仍可补发被拒绝分片，保留已发送正文、其他文件和说明卡。如果先前请求曾丢失响应，重试时收到拒绝不能证明先前未送达；这时保留原请求时间，记录 unknown，并要求确认可能重复后才能人工重试。SDK 异常类型仍继承原 FeishuRuntimeError，通知边界才转换为稳定业务错误；原回复流程的异常捕获保持兼容。

三处旧测试按获批 [补丁](integration-review-proposal.patch) 应用：scheduler 夹具补建通知表，workflow store 夹具补建任务中心表，错误文案测试合并实际运行使用的 backend 翻译源并验证冲突及语言一致性。新增 SDK 测试内容未修改；未删断言、跳过测试或引入生产测试分支。
