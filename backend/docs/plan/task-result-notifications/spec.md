## 1. 依据、目标与范围

产品依据为[完整需求说明](https://sensetime.feishu.cn/docx/X8C8dlvYNoC9joxyb8ScUr7Qnxc)，它已包含此前同步文档的内容。用户已明确：首期实现需求中适用于飞书的全部后端通知功能，后续阶段只增加微信、企业微信等渠道，不能推迟飞书的暂停、全文、产物、多目标或重试能力。

面向创建定时任务并希望通过已有飞书机器人接收状态和结果的用户，提供配置、主动投递、历史、故障恢复的完整后端链路。已有飞书接入提供了账号连接、卡片和消息发送能力，但尚未提供完整的任务通知业务流程。

所有仓库修改限于 `backend/`，含计划、测试、接口源定义、迁移、实现和交接文档。因此计划放在 `backend/docs/plan/task-result-notifications/`，覆盖根 AGENTS.md 的默认计划目录要求。复用 Core、渠道网关、现有账号和出站工作进程；不新增服务、中间件或生产依赖。

前端页面、桌面系统提醒、微信/企业微信通知发送、目录外发布产物和部署配置不在本次实现范围。原有飞书及微信会话回复必须兼容。

## 2. R1 全局设置与 R2 任务规则

- 用户总开关默认开启；成功、失败事件默认开启并选择摘要；暂停默认关闭但保留摘要选择。飞书必须显式启用，不因机器人已连接而发送。
- 全局默认只复制到新建任务；已有任务独立保存。任务支持恢复为当前全局默认。
- 每个事件分别保存 `enabled` 和 `summary/full`；每个渠道分别保存启用状态及多个“账号＋接收对象”绑定。
- 关闭事件或渠道不清除原配置。任务无启用渠道时允许所有事件关闭；存在启用渠道时至少启用一个事件。全局默认事件始终至少保留一个。
- 设置立即持久化并返回版本；并发修改返回冲突，不覆盖其他修改。普通任务规则在执行建立时形成快照，变更从下一次执行生效。
- 总开关关闭前支持影响查询；确认时校验配置版本和影响是否变化。关闭保留配置、任务和历史；重新开启不补发关闭期间已跳过的通知。
- 原创建、批量创建支持通知规则；省略时兼容默认行为。原编辑接口省略通知字段时不得清空规则。

## 3. R3 账号与接收对象

- 稳定账号身份与展示名分离；支持同平台多个账号、同任务多个接收对象和跨任务复用，各目标独立记录结果。
- 群来自机器人可访问的群；个人会话必须来自已验证身份。不接受任意未经验证的接收者。
- 保存和每次发送前校验用户所有权、账号连接状态、接收对象有效性和发送权限。校验无法确认时安全失败或暂缓，不自动改绑其他账号/群。
- 补齐飞书群信息读取权限申请；旧账号缺权限时明确提示补授权，保留原账号和任务引用。
- 用户主动断开保留账号身份、绑定及通知历史；重连必须匹配原身份。同名新账号不能替代原账号。
- 注册失败的孤立账号清理与用户主动断开分别处理。覆盖连接过期、刷新、取消、拒绝授权和网络失败；返回头像、连接状态、时间、任务引用和断开影响。

## 4. R4 事件、摘要、全文与产物

| 真实状态 | 通知事件 |
| --- | --- |
| 执行完成且成功结果已持久化 | 成功 |
| 执行失败 | 失败 |
| 可恢复暂停、等待用户确认、主动停止后进入可恢复等待 | 暂停 |
| 计划停用、等待上游、彻底取消 | 不归入上述事件 |

覆盖正常调度、立即执行、批量创建和依赖调度。修正相关收尾逻辑，不能把仍在等待或仍在执行的任务标成成功。重复上报同一次暂停只产生一个事件，恢复后再次暂停产生新事件。

卡片统一包含任务标题、执行时间和状态。失败展示安全原因，暂停展示原因及待处理事项，不发送未完成的结果。

摘要优先复用来源明确且有效的结果摘要；现有“截取正文前 2000 字符”的字段不能直接当作有效摘要。缺少摘要时使用用户配置的模型、现有纯模型接口生成，禁止任务工具调用；长正文按模型上下文分段归纳，设置生成超时。生成结果持久化，多个目标和重试共用。

摘要生成失败时先发送状态和“摘要暂不可用”，标记内容不完整；补发仅重试缺失摘要的生成，不重跑任务，不重新生成已有摘要或任务结果。

全文为卡片正文加最终产物。长正文按段落顺序分卡；图片和文件原生发送。不适合卡片的内容转文件并说明。无法发送的产物列明名称和安全原因，提示回 LazyMind 查看；继续发送其他内容，记录部分成功，支持仅重试失败部分，不静默截断或漏掉产物。

卡片序列化预算为 28 × 1024 字节，给平台 30 KB 限制留余量；图片和文件分别按现有 10 × 1024²、30 × 1024² 字节限制校验，空文件不可上传。测试覆盖 Unicode、转义扩张、临界值、超限与部分成功。

## 5. R5 可靠投递与历史

Core 保存规则、执行快照、事件、内容快照、通知业务身份和持久化待交接记录；事件与相关任务状态在同一数据库事务中落地。网关保存账号、凭据和实际投递状态。Core 幂等推送并查询同步结果，入队成功不能记为发送成功。

每个目标、正文分片和产物独立记录状态。单个通知失败不改变任务结果、执行次数或其他目标结果；永久失败的产物不阻断其余可用产物。

复用现有出站工作进程：最多自动尝试 5 次，发送请求超时 60 秒，租约 120 秒，每 30 秒续租；按平台限频排队，遵守 Retry-After。旧工作进程失去租约后不能继续写入。

以“执行＋事件实例＋账号＋接收对象”为业务去重边界。重试保持原内容和目标、跳过成功分片，防止并发重复排队。平台请求使用稳定去重标识；飞书 1 小时去重窗口后仍无法确认的分片标记为“发送结果未知”，停止自动重发；人工重试需要明确确认可能重复。

每片发送前重新检查总开关、账号及权限；无法确认时暂缓。总开关关闭使未发送部分失效，重开不能复活旧队列；已经进入平台请求的分片可能完成。按执行查询事件、目标、分片状态和重试关联。

## 6. R6 扩展、权限、部署与迁移

在现有渠道接口上补齐能力查询、目标查询与验证、渲染、发送和错误分类。首期只有飞书声明支持任务通知；微信、企业微信和桌面通知不能被标记为已支持。

新增公开接口沿用 Kong/auth-service 的集中权限体系，同步后端权限注册和 OpenAPI 源定义。公开错误只含稳定业务码、安全说明、必要的公开字段和 request_id；不暴露平台原始错误、凭据、SQL 或内部路径。

Core 使用新增 `LAZYMIND_CHANNEL_GATEWAY_URL`；网关沿用 `LAZYMIND_CHANNEL_GATEWAY_CORE_BASE_URL`，双方使用既有 `LAZYMIND_AUTH_SERVICE_INTERNAL_TOKEN` / `X-LazyMind-Internal-Token` 约定。内部认证缺失不得放行。目录外所需部署改动仅在 backend 内交接，不修改根部署文件。

新增 PostgreSQL/SQLite 兼容 SQL migration，提供 up/down，同步当前已有 v0_3 aggregate；不修改已合并 dev migration。升级不自动启用旧任务的飞书通知，不追溯历史执行。验证新建、升级、回退、数据保留、事务、并发及迁移路径一致性；文件 SQLite 和真实 PostgreSQL 分别运行。

此前已读取的官方依据：[发送消息及去重](https://open.feishu.cn/document/server-docs/im-v1/message/create)、[上传文件](https://open.feishu.cn/document/server-docs/im-v1/file/create)、[群列表](https://open.feishu.cn/document/server-docs/group/chat/list)。群发送须机器人在群且具备发言权限。
