# Local/Desktop 任务工作区（第一迭代）规格

## 背景

LazyMind 的“新建任务”承担 Work 模式能力，但目前不能让用户把本地目录选作任务工作区。第一迭代建立本机工作区授权、任务绑定和权限管理闭环，并为第二迭代的本地文件读写预留统一授权校验边界。

本规格中的“工作区”特指用户在 Local（`make local-up`）或 Desktop 模式中明确授权的本地文件夹；不等同于当前 Agent 内部按会话创建的托管产物目录。

## 目标用户

- 在个人电脑上通过 `make local-up` 使用 LazyMind 的单用户。
- 使用 LazyMind Desktop 的单用户。
- 只在“新建任务”（Work）入口选择本地工作区；“快速问答”（Chat）不获得本地工作区能力。

## 两次迭代边界

### 第一迭代（本计划交付）

- 提供与需求样例一致的“选择工作区”控件、下拉面板和操作流程。
- 通过本机原生目录选择器选择文件夹，并在明确展示授权范围后建立本机授权。
- 保存本机授权工作区列表，并允许搜索、复用和撤销。
- 一个 Work 任务最多绑定一个工作区；首条消息发送并创建任务后锁定绑定。
- 撤销一个工作区时，使所有绑定该工作区的任务立即失效。
- 建立可供第二迭代复用的授权解析与执行前校验接口，但不向 Agent 开放用户目录的读取、创建、修改或命令执行能力。

### 第二迭代（不在本计划中实现）

- 在已绑定且仍有效的工作区内读取、创建和修改文件。
- 每次文件操作执行前及落盘前重新验证授权、任务绑定和规范化路径。
- 拒绝越界路径、失效授权、Chat 模式调用、符号链接逃逸及撤销后的继续访问。

最终验收标准中的文件读写和越界拒绝属于第二迭代；第一迭代只验证权限边界接口在未启用文件能力时安全失败。

## 产品能力

### 模式与部署限制

- Work 模式对应现有“新建任务”/`new_task`。
- Chat 模式对应现有“快速问答”/`quick_question`。
- 工作区入口只在 Local 和 Desktop 的 Work 模式显示。
- Cloud、`make local-up-lan` 和 Chat 模式不得创建、绑定或解析本地工作区。

### 工作区选择 UI

UI 以用户提供的第二、第三张图片为视觉和交互基准：

- “选择工作区”位于“添加”之后、确认方式和思考深度之前。
- 未选择时显示文件夹图标、“选择工作区”和下拉箭头。
- 展开面板包含搜索框、最近工作区名称及完整路径、“打开本地文件夹”和“不使用本地工作区”。
- 当前选择在控件中显示目录名称；完整路径通过面板或提示可见。
- 搜索仅过滤本机有效授权记录，不扫描用户磁盘。
- “打开本地文件夹”调起原生系统目录选择器；取消后不创建授权或绑定。
- “不使用本地工作区”清除尚未发送的新任务选择；已发送任务的绑定不可更改。
- 最近工作区行在默认状态保持与样例图一致；鼠标悬停或键盘聚焦时显示不改变行高的管理操作。管理操作可查看完整授权范围并发起撤销，撤销前必须二次确认。
- 已创建的 Work 任务继续显示同一位置的工作区控件：绑定选择为只读锁定，但可查看名称、完整路径、状态并发起全局撤销。没有绑定的既有 Work 任务显示“不使用本地工作区”且不能补绑。
- 快速问答中不渲染工作区控件，也不通过隐藏字段携带工作区。

### 首次授权弹窗

用户在系统目录选择器中选定一个尚未有效授权的目录后，必须先显示用户提供的第一张新增图片所示弹窗，不能立即创建授权：

- 标题：“首次使用时需要授权”。
- 副标题：“允许 LazyMind 访问“{工作区名称}”工作区？”
- 中部目录卡片显示文件夹图标、目录名称和规范化后的完整真实路径。
- 范围说明：“授权仅适用于该文件夹及其子目录，默认在修改文件前询问。”
- 右上角关闭按钮与底部“取消”行为一致，均不创建授权。
- 主操作按钮为“允许访问”；只有用户点击该按钮后才创建有效授权并把它选为当前新任务的待绑定工作区。
- 弹窗的宽度、圆角、遮罩、标题层级、目录卡片、分隔线、按钮顺序和主按钮颜色以新增第一张图片为视觉基准，并适配小尺寸窗口。
- 从最近工作区列表复用仍有效的授权时不重复显示该弹窗。授权已撤销、路径身份变化或重新授权时必须再次显示。

### 原生目录选择

- Desktop 通过受限 Electron preload/IPC 调用系统目录选择器。
- Local 通过 Local Gateway 的 loopback-only 本机接口调起系统目录选择器；浏览器不直接提供或决定绝对路径。
- Local 原生选择接口仅允许 `make local-up` 的 localhost 配置、可信本机来源及有效本机会话调用；LAN 和非本机来源安全失败。
- 返回路径须由本机端规范化、解析真实路径并验证目录存在且可访问。
- 用户提供的第二张新增图片就是点击“打开本地文件夹”后触发的 macOS 原生系统目录选择器，不由 LazyMind 前端仿制。macOS 以该原生交互验收；标题、确认按钮文字、侧边栏和具体外观由系统控制，可随 macOS 版本变化。该动作只选择原地工作区，不读取或上传目录内容。
- 可信宿主在选择后只签发一个单次、5 分钟有效的候选 `selection_token`，并向前端返回用于首次授权弹窗展示的名称与路径；此时尚未创建授权。前端点击“允许访问”时只提交该 token，宿主验证 token、再次验证目录后，才通过仅宿主可用的认证通道登记授权并返回 `workspace_id`。
- Desktop renderer 和 Local 浏览器前端不得向 Core 提交任意绝对路径。授权完成后，前端可读取用于展示的工作区 ID、名称、完整路径和状态，但创建绑定、撤销等变更请求只提交不透明 `workspace_id`。
- Local 请求必须同时通过 loopback、允许的精确 Origin、本机会话和 CSRF/一次性请求凭据校验；不能仅依赖可伪造的前端运行模式字段。
- 不提供手工输入绝对路径的降级入口。原生选择器不可用时明确提示当前平台能力不可用，且不创建授权。

### 授权模型（方案 A）

- 授权记录只保存在当前 Local/Desktop 实例，不上传云端、不跨设备同步。
- 一条有效授权可被多个 Work 任务分别绑定；从最近列表选择即表示为当前新任务复用该授权。
- 每条授权的根目录就是用户在原生选择器中确认的精确目录。第二迭代中文件操作可访问该根目录及其后代，但不能访问父目录或兄弟目录。
- 即使已经授权父目录，用户把某个子目录选作新任务工作区时仍创建/复用“精确子目录”工作区，不得把任务静默扩大绑定到父目录。
- 授权记录至少包含不透明 ID、显示名称、规范化真实路径、可用时的平台目录身份指纹、状态、来源、授权时间、最近使用时间和版本。身份指纹只用于发现同一路径被替换，不包含目录内容。
- 授权记录预留并固定权限策略：范围为精确根目录及其子目录，读取策略为 `allow`，修改策略默认为 `ask_before_write`。该策略来自首次授权弹窗的明确文案；第一迭代仅保存策略，不启用任何文件内容读取或修改工具。
- 本段记录第一迭代当时的预留策略。第二迭代最终决定已由 `docs/plan/local-task-workspace-file-access/spec.md` 覆盖：第一迭代尚未正式发布，迁移后读取和允许的创建/修改均为 `allow`，绑定任务不逐文件确认；Agent 直接删除、移动和重命名永久禁止，受控程序可在授权工作区内产生必要副作用，也不要求现有未发布授权重新走一次授权弹窗。
- 不保存目录内容、文件清单、文件摘要或 Secret。
- 授权与绑定的业务来源以本机 Core 数据库为准。Desktop 现有 `local-folder-access.json`、file-watcher `allowedRoots` 和目录发现授权不得作为任务工作区授权来源，也不得因第一迭代选择工作区而被扩大；只可复用无副作用的目录选择与路径规范化代码。

### 任务绑定与撤销

- 新任务发送前，工作区只是前端待选状态；创建任务/会话时由后端验证并原子建立绑定。
- 一个任务最多一个绑定。首条消息发送后，绑定不可切换或移除；需要其他工作区时新建任务。
- 撤销工作区是显式用户操作，确认界面展示完整路径和受影响任务数量。
- 撤销成功后，该授权变为失效；所有相关任务的绑定状态通过该授权即时派生为 `revoked`，不依赖逐条异步更新。历史任务仍可查看对话，但不得再解析为可访问工作区。
- 重新授权同一路径不会静默恢复旧任务绑定；旧任务保持失效，新任务可绑定新的有效授权。这样避免撤销语义被后续授权反向绕过。
- 若工作区在另一个窗口中于发送前被撤销，首次创建请求必须失败且不留下工作区绑定；前端保留用户输入并要求重新选择。
- 归档任务不解除绑定且计入撤销影响范围；永久清除任务时同步清除其绑定。撤销记录保留最小审计元数据，不保留文件内容。

绑定状态只允许以下单向变化：

- 新任务待选 `none` → 创建时 `active`；创建后不能切换或补绑。
- `active` → 授权撤销后 `revoked`。
- `active` → 目录移动、删除、不可访问或同一路径身份指纹变化后 `path_unavailable`；不得仅因同一路径再次出现而自动恢复，必须重新走原生授权并建立新的授权身份。
- 第二迭代中文件操作除检查绑定状态外，还必须执行授权策略；写操作没有本次明确确认时保持拒绝。

### 第二迭代扩展边界

第一迭代提供单一的“按任务解析有效工作区”服务边界。它必须验证：

1. 服务端配置确认当前部署为 Local 或 Desktop 且不是 LAN；不信任客户端 `VITE_LAZYMIND_MODE`。
2. 请求属于 Work 任务。
3. 调用者拥有该任务。
4. 任务存在唯一绑定。
5. 授权仍有效。
6. 当前真实路径仍与授权根一致。

第一迭代调用该边界只能取得不对 Agent 暴露的内部工作区描述；文件工具、file-watcher 和执行器不得消费它。第二迭代在此边界上执行已授权策略、操作类型和候选路径校验，不另造平行授权体系。

## API 与数据设计骨架

具体路由名和存储表名在测试阶段结合现有 Core 契约确定，但公开行为必须覆盖：

- 列出当前本机有效授权工作区；任务绑定查询可返回对应的已撤销记录和状态，以便历史任务解释失效原因。
- 由可信 Local/Desktop 宿主登记原生选择器返回的目录；公开浏览器 API 不接受路径字段。
- 撤销工作区并返回受影响任务数。
- 在首次创建 Work 任务时提交可选 `workspace_id` 并建立绑定。
- 获取任务的工作区绑定状态：`active`、`revoked`、`path_unavailable`、`missing` 或 `none`。
- 内部解析接口为第二迭代返回有效授权根；未启用文件能力时拒绝文件操作。

Local 与 Desktop 的主要业务库均为 SQLite。本功能不得改变 Docker Compose/PostgreSQL 和 Cloud 行为；若 Core 使用迁移保存授权与绑定，迁移必须同时兼容 PostgreSQL 与 SQLite，即使 Cloud 路由保持禁用。

## 稳定错误语义

第一迭代为以下语义预留连续且当前未占用的 Core 错误码。Core 继续使用现有 `{code, message, data}` 数值错误信封；Local/Desktop 宿主边界可返回对应语义名，前端须归一化为同一用户提示：

| 语义 | Core 错误码 | HTTP | 使用场景 |
| --- | ---: | ---: | --- |
| `LOCAL_WORKSPACE_MODE_FORBIDDEN` | `2002321` | 403 | Cloud、LAN 或 Chat 模式调用 |
| `LOCAL_WORKSPACE_SELECTION_FORBIDDEN` | `2002322` | 403 | 非本机来源或无有效本机会话调起选择器 |
| `LOCAL_WORKSPACE_SELECTION_EXPIRED` | `2002323` | 410 | 候选选择 token 已过期或已使用 |
| `LOCAL_WORKSPACE_SELECTION_INVALID` | `2002324` | 400 | token 无效、被篡改或与当前本机会话不匹配 |
| `LOCAL_WORKSPACE_PATH_INVALID` | `2002325` | 400 | 路径不存在、不是目录、不是绝对路径或真实路径解析失败 |
| `LOCAL_WORKSPACE_NOT_FOUND` | `2002326` | 404 | 工作区 ID 不存在或不属于当前本机用户 |
| `LOCAL_WORKSPACE_REVOKED` | `2002327` | 409 | 工作区已撤销 |
| `LOCAL_WORKSPACE_BINDING_LOCKED` | `2002328` | 409 | 已创建任务尝试切换、移除或补充绑定 |
| `LOCAL_WORKSPACE_BINDING_CONFLICT` | `2002329` | 409 | 任务已有其他绑定或并发绑定冲突 |
| `LOCAL_WORKSPACE_PATH_UNAVAILABLE` | `2002330` | 409 | 已授权目录被移动、删除或当前不可访问 |
| `LOCAL_FILE_ACCESS_NOT_ENABLED` | `2002331` | 501 | 第一迭代中任何文件操作入口被调用 |

对外错误不得包含异常原文、系统调用详情、SQL、内部路径或堆栈。仅在用户主动选择、查看或撤销工作区的界面展示其完整授权路径。

## 非功能要求

- 安全失败：部署模式、任务类型、所有权、授权状态或真实路径任一不明确即拒绝。
- 并发一致性：任务唯一绑定和撤销必须依赖事务及数据库约束，不依赖前端防重。
- 防伪造：只有可信 Local/Desktop 宿主能登记路径；renderer、网页请求和模型输出不能把任意字符串变成授权。
- 可恢复性：应用或服务重启后授权和绑定状态保持一致；损坏或无法读取的本机授权状态按无授权处理。
- 隐私：授权路径不进入普通聊天消息、模型提示、遥测或非必要日志。
- 跨平台：Desktop 支持项目现有 macOS/Windows 目标；Local 原生选择覆盖项目声明支持的本机平台。每个平台使用受控参数调用并校验退出状态，缺少系统选择器时给出明确错误且允许用户重试，不降级为 shell 拼接或不受控路径提交。
- 性能：最近列表默认最多展示 8 条，按最近使用时间倒序；搜索在已授权记录内完成。
- 无障碍：选择控件、搜索、列表项、撤销确认和错误状态可用键盘操作并具有可读标签。

## 不做项

- 第一迭代不读、写、创建、删除、移动或搜索用户工作区文件。
- 系统目录选择只取得目录元数据用于显示和授权，不上传目录或其内容。
- 不允许命令执行，不修改 Agent sandbox 权限。
- 不支持一个任务绑定多个工作区。
- 不在 Cloud、Docker Compose、LAN 或 Chat 模式提供本地工作区。
- 不同步授权记录到账号或其他设备。
- 不扫描磁盘生成最近工作区；只展示用户明确授权过的目录。
- 不复用或扩大知识库/file-watcher 的本地目录扫描权限。
- 不修改无关前端、算法或生成产物。

## 第一迭代完成标准

- 三种入口/部署限制、选择、授权、复用、锁定、撤销和失效行为均有自动化测试。
- Local 与 Desktop 均能从图片对应入口调起原生目录选择并完成 Work 任务绑定。
- UI 与提供图片在结构、顺序、状态和主要视觉尺寸上保持一致，并完成截图或人工视觉核对。
- 撤销后所有关联任务立即返回 `revoked`，且内部解析失败。
- Chat、Cloud、LAN、跨站请求、伪造路径、越权任务和无效路径安全失败。
- 文件操作能力仍关闭，测试证明第一迭代不会把真实路径交给 Agent 文件工具。
- 契约、错误目录、实现、迁移与 Local/Desktop 配置一致，SQLite 验证通过，并证明 PostgreSQL/Cloud 未被破坏。
