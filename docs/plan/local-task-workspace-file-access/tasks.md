# Local/Desktop Work 任务本地工作区实施任务

- 任务 1～9 的范围收敛、LazyLLM 恢复和自动化回归已完成。
- 任务 10 的自动化部分已通过；真实 Local/Desktop E2E 尚未执行。
- Windows 人工验收已由用户豁免，Windows 自动测试和交叉编译已通过。
- 用户确认代码边界：不修改 LazyLLM，业务实现尽量位于 Backend；`algorithm/lazymind/`、`local/`、`desktop/` 只保留不可替代的宿主/Agent改动。

## 1. 固化范围和交互契约

- 以最初需求和用户补充交互图为唯一产品范围。
- 固定 Work/Chat、Local/Desktop/其他部署模式矩阵。
- 固定工作区菜单、授权弹窗、权限菜单、风险框、取消和反馈行为。
- 删除资源调度、全局 Office 改造和通用压缩审批等超范围要求。
- 恢复官方 LazyLLM 子模块和原固定版本，删除补丁；后端适配不得修改外部子模块。

## 2. 工作区授权模型

- 保存本机用户授权的目录名称、规范路径、目录身份、状态和版本。
- 支持授权列表、最近使用、撤销和失效状态。
- 同一路径重新授权创建新授权，不恢复旧任务。

## 3. Work 任务绑定

- 新 Work 任务可原子绑定一个已授权工作区。
- 已有任务不能换绑其他工作区。
- Chat、Cloud、LAN 和普通服务模式拒绝绑定。
- 任务绑定保存三档权限及版本。

## 4. 原生目录选择

- Local Proxy 调用本机原生目录选择器并生成短期一次性候选 token。
- Desktop main/preload 暴露最小目录选择与授权桥。
- Renderer 不能直接提交任意主机路径。
- 目录选择不改变 file-watcher 或知识库授权。

## 5. 文件能力

- 接入工作区相对路径的列表、搜索、读取、创建目录、创建文件、覆盖、追加和文本替换。
- 不注册删除、移动、重命名、链接或权限修改文件 API。
- 保留文本大小、读取窗口和目录/搜索结果的合理硬限制，不建设扩容审批体系。

## 6. 权限边界

- 规范化并拒绝绝对路径、`..`、驱动器/UNC 越界和空字节。
- 检查符号链接、目录身份和最近存在父目录。
- 操作前与提交前复核授权；修改使用版本冲突和原子提交。
- 子 Agent 和 Skill 继承同一任务范围，不得扩大授权。

## 7. 三档权限

- `always_ask`：文件编辑、联网和已连接应用副作用询问。
- `ask_as_needed`：仅风险操作询问，作为默认值。
- `allow_all`：风险框确认后跳过可批准询问，但永久禁止项不放行。
- 切换前 pending 操作不自动批准。
- 复用项目已有一次性批准链，不新增复杂长期队列或资源调度系统。
- 在 LazyMind `ToolCallGuard` 中完成批准重放和已连接应用前置确认；工作区命令使用 LazyMind 同名安全适配器覆盖 LazyLLM 内置工具。

## 8. 前端交互

- 新 Work 默认“选择工作区”和“按需确认”，不默认选目录。
- 工作区搜索、直接切换、失效重授权、原生选择和不使用工作区。
- 权限入口禁用状态、三档菜单和全部允许风险框。
- 两个菜单互斥；空白、遮罩、关闭和 `Esc` 行为正确。
- 成功提示和越界阻止提示完整。

## 9. 契约和迁移

- Core API、OpenAPI、生成客户端、错误目录和前端类型保持一致。
- PostgreSQL/SQLite 创建、升级和回退保留工作区、绑定和权限模式数据。
- 不新增本需求范围外的资源批准表或服务。

## 10. 验证

- Core：授权、绑定、撤销、权限模式、模式门禁和迁移测试。
- Local Proxy/Desktop：原生选择、一次性 token 和最小桥测试。
- Algorithm：文件读/建/改、越界、撤销和三档权限测试。
- Frontend：全部工作区及权限交互契约、无障碍和视觉核对。
- E2E：Local 与 Desktop 完成选择授权—Work 任务—读/建/改—撤销闭环。
- Windows 人工验收按用户要求豁免；保留自动测试和交叉编译。
