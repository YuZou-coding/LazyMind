# Local/Desktop Work 任务本地工作区规格

## 1. 目标

LazyMind 在 Local 和 Desktop 的 Work（新建任务）模式中，允许用户选择一个本地文件夹作为当前任务工作区。任务可在用户明确授权的范围内读取、创建和修改文件，用于文档处理、内容生成和其他复杂任务。

本功能不得把“运行在本机”等同于获得任意本地文件权限。Chat（快速问答）以及未启用本机工作区能力的部署模式不能访问用户文件。

## 2. 部署和任务范围

- Local（`make local-up`）和 Desktop 的 Work 任务开放本地工作区。
- Chat 模式不显示工作区入口，也不能取得本地文件能力。
- Cloud、LAN 和普通 Docker Compose 服务模式默认不开放；部署方可选择完全不提供该能力。
- 每个 Work 任务最多绑定一个工作区；同一授权工作区可以被多个 Work 任务复用。
- 已创建任务的工作区绑定不可改为其他目录；可以查看状态和撤销授权。
- LazyLLM 保持官方仓库固定版本，不在本需求中修改；权限适配由 LazyMind 后端完成。

### 代码改动边界

- 业务逻辑优先放在 `backend/` 与 `frontend/`。
- `algorithm/lazymind/` 仅承载 Agent 文件工具和批准适配；不得修改 `algorithm/lazyllm/`。
- `local/local-proxy/`、`local/local-runtime-manager/` 和 `desktop/` 仅允许包含原生目录选择、可信宿主授权和本地启动注入所必需的最小改动。
- Office 转换、其他业务模块和外部依赖保持 `origin/main`。

## 3. 工作区授权

- 用户必须通过系统原生目录选择器选择目录。
- 首次使用目录时，LazyMind 展示二次授权弹窗，明确文件夹名称、路径和访问范围。
- 授权范围是该目录及其子目录。
- 取消、关闭、点击遮罩或按 `Esc`：不授权、不切换。
- 点击“允许访问”：完成授权并切换到该工作区。
- 已授权工作区可直接切换并关闭菜单。
- 已撤销或不可用的历史工作区再次点击时，必须重新走原生选择和授权流程；新授权不能恢复旧任务。
- 用户可以查看已授权工作区并撤销授权；撤销后所有绑定任务立即不能发起新的文件访问或提交修改。

## 4. 文件能力

任务只接收工作区相对路径，允许：

- 列出和搜索工作区文件；
- 读取文件和必要的文档解析结果；
- 创建目录；
- 创建文件；
- 覆盖、追加和精确修改已有文件。

文件 API 不提供通用删除、移动、重命名、链接、权限或所有权修改能力。项目原有命令工具可以继续使用，但必须遵守当前任务工作区和权限模式，不能由本功能扩展成新的通用命令平台。

## 5. 必要安全边界

- 拒绝绝对路径、`..`、空字节、驱动器/UNC 越界和工作区外路径。
- 拒绝通过符号链接、目录替换或同路径重建逃逸授权范围。
- 文件操作执行前及提交前重新验证用户、Work 任务、绑定、授权状态和目录身份。
- 普通文件修改使用版本校验和同目录原子替换，避免静默覆盖和半文件。
- 工作区撤销或目录身份变化后安全失败。
- 模型、公开 API、普通聊天、日志和提示词不暴露不必要的完整主机路径。
- 主 Agent、子 Agent 和 Skill 不得扩大当前任务的工作区范围。
- 永久禁止越界、提权、系统破坏、权限/所有权修改以及其他不能合理授权的操作。

这些措施用于落实最初的权限边界，不构成额外产品功能。

### LazyMind 后端适配边界

- LazyLLM 固定为官方 `084d4905`，不携带本需求修改。
- LazyMind `ToolCallGuard` 负责剥离模型伪造的内部批准参数、处理 `needs_approval`、等待用户决定并精确重放原调用。
- 工作区任务通过 LazyMind 自有同名 `shell_tool` 适配器覆盖 LazyLLM 内置 Shell；适配器固定授权根、采用结构化参数、限制环境和输出，并在运行中复核撤销。
- MCP 工具名称由 LazyMind 后端标记；`always_ask` 在首次调用前完成确认，不修改 LazyLLM MCP adaptor。

## 6. 三档任务权限

权限模式保存在 Work 任务与工作区绑定上：

### 始终询问 `always_ask`

- 普通读取和安全只读操作直接执行。
- 文件创建/修改以及联网操作逐次询问。
- 已连接应用产生外部副作用时逐次询问。

### 按需确认 `ask_as_needed`

- 默认模式。
- 工作区内普通文件操作直接执行。
- 仅项目已有风险识别命中的命令、联网、敏感文件或其他风险操作询问。

### 全部允许 `allow_all`

- 选择后先展示风险确认框，不立即生效。
- 风险框说明文件和文件夹、命令和系统操作、互联网和已连接应用风险。
- 取消、关闭、遮罩或 `Esc` 保持原权限。
- 点击“确认开启”后，当前任务跳过原本可人工批准的询问。
- 不得绕过工作区边界、撤销、提权、系统破坏或其他永久禁止项。

权限切换只影响之后的操作，不自动批准切换前已经等待的操作。

## 7. 前端交互

### 默认状态

- 新建 Work 默认显示“选择工作区”。
- 不默认选中 LazyMind 或其他目录。
- 默认权限为“按需确认”。
- 工作区菜单、权限菜单和风险弹窗默认收起。
- 未选择工作区时权限入口不可用。

### 工作区菜单

- 点击工作区入口展开或收起。
- 根据名称和路径实时搜索。
- 点击有效授权：直接切换并关闭菜单。
- 点击失效授权：展示“首次使用时需要授权”弹窗。
- “打开本地文件夹”调用系统原生目录选择器；取消保持当前工作区。
- “不使用本地工作区”清除当前任务选择并禁用权限入口。

### 权限菜单

- 点击权限入口展开或收起。
- 包含“始终询问 / 按需确认 / 全部允许”。
- 前两项立即切换。
- “全部允许”先展示风险确认框，确认后才生效。
- 工作区菜单和权限菜单互斥，不会同时展开。

### 通用反馈

- 工作区切换、授权和权限修改成功后展示短暂提示。
- 点击空白处或按 `Esc` 关闭菜单和弹窗。
- 越界访问展示明确的权限阻止提示。

## 8. 非目标（避免过度开发）

- 不新增通用命令执行产品，只约束项目已有命令能力。
- 不建设固定 4 读/2 命令/1 写的资源调度系统。
- 不建设跨请求读写租约、复杂 FIFO 或长期批准持久化系统。
- 不为本需求改造全局 Office 转换服务。
- 不建设 10,000 条目、500 MiB 解包量和精确扩容批准等通用压缩资源审批体系。
- 不新增平行权限表、平行授权来源或与现有任务工作区无关的服务。

## 9. 验收结果

- 用户可在 Work 模式选择并授权本地文件夹。
- LazyMind 可在授权范围内读取、创建和修改文件。
- 工作区外访问被拒绝并明确提示。
- 撤销后绑定任务不能继续访问。
- Chat 和未启用部署模式不能访问本地工作区。
- 三档权限及所有菜单、弹窗、取消和反馈交互符合用户提供的图例。
