# Local/Desktop 任务工作区文件访问（第二迭代）规格草案

> 状态：第二迭代主体已进入实现；任务级三档权限补充需求已确认，补充阶段一测试待 Review。

## 背景

第一迭代已经建立 Local/Desktop 工作区的原生选择、明确授权、Work 任务绑定、授权复用、全局撤销和失效状态。第二迭代在这条单一授权边界上开放真实文件能力，使 LazyMind 能在用户明确授权的工作区内完成文档处理、内容生成、代码分析和其他复杂任务。

本迭代不得把“运行在本机”本身视为文件权限，也不得继续使用现有 Trusted Local 模式中允许任意绝对路径的宽泛行为。所有文件和命令操作都必须由当前用户、当前 Work 任务及其唯一工作区绑定共同授权。

## 已确认的产品决定

1. 文件能力范围选择严格方案：允许列出、搜索、读取、创建目录、创建文件、覆盖、追加和修改文件；不提供移动、重命名或删除。
2. 用户首次明确授权工作区后，绑定该授权的 Work 任务可直接读取、创建和修改文件，不再逐文件申请确认。
3. 主 Agent、所属子 Agent 和 Skill 均可使用同一工作区能力；正常工作区命令通过项目已有命令工具体系执行。
4. 危险命令沿用现有危险识别、`ToolExecutionError.approval_required` 和 `needs_approval` 语义，同时增加任务工作区边界。
5. 普通命令以及工作区范围内的删除、移动和重命名命令直接执行；其他可合理使用的高风险命令逐次确认；提权、系统破坏和越界操作永久禁止。受控构建、格式化、测试和包管理程序可在授权工作区内产生必要的删除/移动副作用。
6. 高风险命令采用真正的交互式批准闭环：一次性批准、10 分钟过期、拒绝后 Agent 可继续寻找替代方案。
7. 文件和命令资源限制采用已确认的推荐值，优先复用项目现有默认值。
8. 每个绑定工作区的 Work 任务保存独立的权限模式，允许值为 `always_ask`（始终询问）、`ask_as_needed`（按需确认）和 `allow_all`（全部允许）；新任务和升级前已有任务均默认 `ask_as_needed`。
9. `allow_all` 只跳过原本允许人工批准的文件、命令、联网和已连接应用操作；工作区越界、提权、系统破坏、权限/所有权修改及其他永久禁止项始终不能放行。
10. `always_ask` 对文件创建、修改、删除、移动、重命名，以及联网和已连接应用操作逐次确认；普通文件读取与安全的本地只读命令直接执行。
11. 通过原生目录选择器选中未授权目录后仍展示 LazyMind 首次授权弹窗；已授权目录直接切换。重新授权已撤销工作区时创建新的授权记录，不恢复旧任务访问权限。

## 目标用户与部署范围

- 通过 `make local-up` 使用 LazyMind 的本机用户。
- 使用 LazyMind Desktop 的本机用户。
- 只对“新建任务”/Work/持久化后台任务开放。
- “快速问答”/Chat、Cloud、Docker Compose 服务模式和 `make local-up-lan` 不获得本地工作区文件能力。

## 授权语义

### 工作区授权

- 精确范围仍为用户原生选择器确认的目录及其子目录。
- 授权策略调整为读取 `allow`、创建和修改 `allow`。
- 首次授权弹窗必须明确说明授权后可在绑定任务中读取、创建和修改文件，不再显示“默认在修改文件前询问”。
- 弹窗沿用已确认的授权范围文案，不额外列举删除、移动和重命名；系统仍不得访问工作区外路径或获得本机提权能力，受控工具可能在工作区内更新或清理自己的构建、依赖和缓存文件。
- 第一迭代尚未正式发布，本迭代按最终授权语义同步未发布的契约、默认值和测试；不设计面向正式用户的静默权限升级路径。

### 任务绑定

- 文件能力只能从已有的唯一任务工作区绑定派生，不新增平行授权来源。
- 主 Agent、子 Agent 和 Skill 共享所属 Work 任务的同一精确根目录，不能扩大范围或改绑其他工作区。
- 任务没有绑定、授权已撤销、路径不可用、任务所有权不明或任务不是 Work 时安全失败。
- 撤销提交后，所有绑定任务、子 Agent、Skill 和未执行操作立即不能发起新访问或提交写入；仍在运行的命令进入取消流程并最迟 5 秒终止进程树。
- 权限模式属于任务与工作区绑定，不属于可被多个任务复用的目录授权。同一工作区可以被多个任务以不同权限模式使用。
- 新任务在首次请求中提交工作区 ID 和权限模式并原子创建绑定；已有任务通过受所有权保护的接口修改模式。权限模式变化不改变工作区授权版本，也不影响绑定同一授权的其他任务。
- 升级前已有绑定通过数据库迁移补为 `ask_as_needed`；无工作区的任务不创建虚假绑定或权限记录。

### 三档权限模式

- `always_ask`：普通读取和安全只读命令直接执行；文件创建、覆盖、追加、文本替换、删除、移动、重命名，以及任何联网或已连接应用操作进入逐次批准。
- `ask_as_needed`：普通工作区读写以及范围内删除、移动、重命名直接执行；现有风险识别命中的命令、联网、敏感文件和资源扩容进入逐次批准。
- `allow_all`：在风险确认框确认后，原本属于“可批准”的文件、命令、联网及已连接应用操作直接执行；敏感文件正文仍按最小披露和脱敏规则处理。
- 三种模式均不改变工作区根目录、任务所有权、授权状态、资源硬上限和永久禁止集合。任何客户端或模型提交的模式都必须由 Core 当前绑定状态校验，不能在工具参数中临时覆盖。
- 模式切换即时作用于该任务后续尚未开始的操作；已经处于等待中的批准不会因切换到 `allow_all` 自动执行，必须由用户处理或取消，以避免旧载荷被静默放行。

## 允许的文件能力

### 无需逐次确认

- 列出目录和读取文件元数据。
- 按名称或 glob 搜索文件。
- 在文本文件中搜索内容。
- 分段读取普通文本、代码和配置文件。
- 通过既有解析能力读取 PDF、Office、图片及支持的文档格式。
- 创建目录和必要的父目录。
- 创建普通文本、代码、配置及 Skill 生成的文档文件。
- 覆盖、追加和精确修改现有文件。
- 通过既有 Skill 生成完整的新 PDF、Office、图片或其他支持的二进制结果并安全写回。

### Agent 可见能力永久禁止

- 删除文件或目录。
- 移动或重命名文件或目录。
- 递归删除、通配删除及等价命令。
- 创建符号链接或硬链接。
- 修改文件权限、所有者、ACL 或扩展系统属性。
- 访问授权根的父目录、兄弟目录或其他任务工作区。
- 挂载目录、设备或网络文件系统。
- 通过 Shell、解释器、Skill、压缩包、Git 配置、环境变量或子进程绕过授权边界。

这里禁止的是用户、模型或 Skill 通过文件工具直接请求删除、移动或重命名，也禁止把等价通用工具暴露给 Agent。可信执行器可以为原子覆盖清理自身 staging；经过命令策略和 containment 的构建、格式化、测试及包管理程序可以在授权工作区内删除或移动自己的缓存、依赖和生成物。该放宽不适用于工作区外、提权、系统路径、权限/所有权、链接或挂载操作。

由于任意项目代码的内部文件副作用无法仅靠命令文本可靠区分，产品不承诺“运行普通/已批准程序时工作区内绝不发生删除或移动”。Agent 直接提出 `rm`、`mv`、`del`、`Move-Item` 等删除、移动或重命名意图时，只要目标全部位于工作区内即可直接执行，越界时永久拒绝。

因此，工作区外不可访问是强安全边界；文件 API 不提供直接删除/移动工具，命令入口可直接删除、移动或重命名工作区内目标。常见直接意图、解释器内联删除和等价包装必须先识别目标范围，越界即拒绝，但不能用该识别替代备份或版本控制。该限制必须在交付文档中保持一致。

## 文件路径安全边界

每次操作执行前及真正提交前均必须：

1. 验证受控运行配置为 Local 或 Desktop 且不是 LAN。
2. 验证当前用户拥有当前 Work 任务。
3. 解析任务唯一绑定并验证授权状态与版本。
4. 重新检查当前目录真实路径和平台目录身份。
5. 只接受工作区相对路径；模型、前端和普通工具参数不得提交任意绝对主机路径。
6. 规范化路径并拒绝空字节、驱动器切换、UNC 越界、`..` 逃逸和平台歧义。
7. 对现有路径解析全部符号链接；对新路径解析最近存在父目录并拒绝链接逃逸。
8. 提交前重新解析父目录、重新校验授权并检查目标文件指纹。

完整主机路径只允许存在于可信本机执行边界和用户主动查看的授权管理界面，不进入模型提示、普通聊天消息、遥测或普通日志。

### 句柄锚定与竞态防护

两次 `realpath` 检查不能单独作为安全边界，因为目录或符号链接可能在“检查完成”与“打开文件”之间被替换。可信本机执行器必须把已验证的工作区根保持为操作系统目录句柄，并从该句柄逐段解析目标：

- Unix/macOS 使用目录文件描述符、相对打开和 no-follow 语义；不得在校验后回退为拼接绝对路径调用普通 `open`。
- Windows 使用目录 Handle、禁止 reparse-point 跟随的打开方式及最终句柄路径复核；拒绝驱动器和卷切换。
- 新建文件和目录时逐级打开最近存在父目录，并在同一已验证父句柄下创建。
- 覆盖时在同一父目录创建临时文件，并通过同一目标名完成内部原子提交。
- 测试必须在校验与打开/提交之间并发替换父目录和符号链接，证明操作仍不能逃逸。
- 平台无法提供上述句柄级保证时，文件操作安全失败，不降级为字符串前缀检查。

## Agent、子 Agent 与 Skill

- 复用现有 Agent 工具注册、ToolManager、工具执行结果和并发控制机制。
- 主 Agent、子 Agent 和 Skill 必须从任务运行上下文取得不透明工作区能力，而不是自行读取环境变量或数据库。
- 模型只看到工作区相对路径和允许的工具描述。
- 子 Agent 请求必须保留所属主任务身份；脱离任务或跨任务复用的能力无效。
- Skill 可以读取、创建和修改文件，也可以调用允许的工作区命令，但不得直接取得无约束的主机文件权限。
- 现有 Trusted Local 中允许任意绝对路径和任意 Shell 的提示与行为不得作用于绑定本地工作区的 Work 任务。

### Skill 执行模型

- 内置 Skill 与用户安装的第三方 Skill 使用相同权限边界，不因来源不同自动获得更高权限。
- Skill 的普通文件读写优先使用任务工作区受控文件工具。
- 需要运行脚本的 Skill 继续复用现有 SkillManager 与 sandbox 接口，但不能使用当前仅复制脚本、继承完整主机环境的 DummySandbox 作为最终权限边界。
- Skill 脚本只获得：只读的 Skill 源码、受控运行时依赖、任务工作区受限视图和专用临时目录。环境变量采用 allowlist，不继承主进程全部环境。
- 平台 Skill sandbox 必须在系统调用层禁止工作区外访问，以及任何链接创建、权限修改、提权和后台进程逃逸；工作区内删除/移动可作为受控程序的内部副作用，或由 Agent 通过命令入口直接执行，但不得通过 Agent 文件 API 暴露。脚本内调用 Python、Node 或子进程也不能扩大到工作区外。
- sandbox 不可用时，Skill 仍可通过受控文件 API 工作，但本地脚本执行明确返回能力不可用，不降级到无约束 `subprocess`。

## 命令执行策略

### 正常命令

正常命令在工作区执行，不需要额外确认，例如只读检查、搜索、格式化、测试、构建和受支持的文档处理命令。执行器必须固定工作目录、清理敏感环境、限制时间/输出/并发，并阻止越界参数和进程逃逸。

正常命令不再原样调用现有 `shell=True` 路径。模型提交的命令先复用现有危险识别，再进入工作区命令执行器：

- 无 Shell 元字符的检查类命令解析为结构化 argv，以 `shell=false` 运行；命令名、cwd 和所有可识别路径参数必须通过策略校验。
- 命令替换、重定向、任意解释器内联代码、包管理和网络访问按现有危险逻辑或等价风险进入逐次批准；安全管道和条件执行必须先被结构化解析，无法完整解析时不直接执行。获批命令仍在平台 containment 中运行。
- 允许的正常命令最小集合包括项目已有的目录/搜索工具、只读 Git 查询，以及经识别的项目格式化、测试、构建和文档处理命令；后四类只有在平台 containment 可用时才能直接执行。
- 只读 Git 查询必须设置等价于 `GIT_OPTIONAL_LOCKS=0` 的受控环境并阻止 hook、pager 和外部 helper，避免查询为了刷新索引而写入 `.git/**` 或启动未受控程序。
- `env` 只接受执行器定义的 allowlist；HOME、凭据、代理、动态库注入和运行时搜索路径不得由模型覆盖。
- 命令预检必须识别显式敏感文件参数和受保护路径；读取敏感文件先进入一次性批准，`.git/**` 等版本控制内部目录对命令保持只读。任意项目代码可能动态计算路径，因此 runner 还必须通过受限文件视图隐藏未批准敏感文件的正文并阻止受保护目录写入，不能只依赖 argv 扫描。

### 平台 containment 契约

- 继续复用现有 `shell_tool` 的工具名、危险词检测、错误封装和 ToolManager 调用链；实际进程创建委托给 Local/Desktop 工作区命令 runner。
- runner 必须保证进程及其后代只能读取必要的系统运行时/工具链和授权工作区，只能在工作区允许范围及专用临时目录写入。
- runner 必须在系统调用层拒绝工作区外文件访问，以及链接、权限/所有权、提权、挂载和系统破坏行为；可在授权工作区和专用临时目录内允许受控程序的删除/移动副作用。Agent 直接删除、移动或重命名命令必须先验证所有目标均在工作区内，通过后直接执行；仅靠命令字符串黑名单不算越界 containment。
- macOS、Linux 与 Windows 分别提供平台适配器，并通过真实逃逸测试验收；Linux 属于 `make local-up` 的现有选择器目标，不能遗漏。某个平台缺少可验证适配器时，该平台命令和 Skill 脚本功能安全失败；普通受控文件 API 仍可使用。
- 能执行工作区代码的测试、构建、解释器和 Skill 命令，即使名称未命中现有危险词，也必须进入 containment；其中已识别的项目测试、构建可作为普通命令直接运行，任意解释器内联代码仍逐次批准。
- 包管理命令批准后仍只能在项目本地依赖目录、项目虚拟环境或专用缓存内创建、修改、删除和移动；系统级、用户全局和共享运行时安装永久禁止。
- 同一命令同时命中网络、包管理、敏感文件等多种风险时合并成一个决定，卡片逐项展示全部原因；一次允许只授权卡片列出的命令、精确敏感文件和风险集合，不能隐式扩大读取范围。

### 可批准的高风险命令

继续复用项目已有危险命令识别语义。包管理、网络下载、Shell 重定向及其他项目已有逻辑判定为可合理使用的高风险命令，返回 `needs_approval` 并暂停当前 Work 任务。

确认卡片至少显示：

- 完整命令的安全展示文本。
- 工作区名称和相对执行目录。
- 被判定为高风险的原因。
- 是否访问网络、安装依赖或使用 Shell 重定向。
- “拒绝”和“允许本次执行”。

批准记录必须绑定用户、任务、工作区授权及版本、规范化命令、相对执行目录和危险原因。批准只能使用一次，10 分钟后过期；命令、参数、目录、授权版本或任务身份变化均须重新申请。模型不能自行设置或伪造 `allow_unsafe`。

用户拒绝后，将结构化拒绝结果返回 Agent，允许 Agent 寻找替代方案。运行时重启使未消费的短期批准安全失效；用户可以让 Agent 重新申请。

### 永久禁止命令

以下直接命令意图或等价 Agent 请求直接拒绝，不提供批准按钮：工作区外的删除、移动或重命名、提权、权限/所有权修改、磁盘和挂载操作、关机重启、任意进程终止、Git 破坏性清理或硬重置、Git 全局配置、后台常驻进程、符号/硬链接创建、系统配置修改和任何越界访问。工作区范围内的删除、移动和重命名在目标校验通过后直接执行；受控构建、格式化、测试和包管理程序在工作区内的内部删除/移动副作用不按直接命令处理。执行器仍必须能够在超时、撤销或任务取消时终止由该次受控命令创建的进程树。

## 文件类型与资源限制

### 目录与搜索

- 单次目录列表最多 200 项。
- 默认递归深度 5 层。
- 搜索默认最多 50 条、明确提高时最多 200 条。
- 搜索命令默认超时 30 秒。
- 默认忽略 `.git` 内部目录、依赖、构建和缓存目录；用户指定路径时仍不得写入 `.git` 内部管理文件。

默认忽略集合固定为：`.git/**`、`.hg/**`、`.svn/**`、`node_modules/**`、`.venv/**`、`venv/**`、`__pycache__/**`、`.cache/**`、`dist/**`、`build/**`、`out/**`、`target/**` 和 `coverage/**`。显式指定某个范围内路径时可读取普通文件，但 `.git` 内部管理文件始终只读；`.gitignore`、`.gitattributes` 等工作树文件按普通文本处理。

### 文本

- 单个文本源和修改后的目标文本文件最大 20 MiB。
- 每次返回模型的文本窗口最多约 10 KiB。
- 默认读取 2,000 个逻辑行，最高 4,000 行。
- 文本写入最大 20 MiB，使用同目录临时文件、同步关闭和安全替换。

### PDF、Office、图片与其他二进制文件

- 模型不直接接收原始二进制字节。
- PDF、Office、图片通过项目既有解析、转换和对应 Skill 处理。
- 单个二进制输入和单个生成文件最大 100 MiB。
- 不提供任意二进制局部补丁；修改由受控 Skill 生成完整结果并安全写回。

Office 与压缩容器采用以下默认解包预算：最多 10,000 个条目、解包后总量 500 MiB、单个条目 100 MiB，并禁止自动递归解包嵌套压缩包。绝对路径、`..`、符号/硬链接、设备条目和跨卷条目永久拒绝，不能通过批准放行。

预计会超过条目数或解包大小默认值时，任务在解包前生成一次性 `needs_approval`。确认卡片显示源文件相对路径、文件指纹、默认值及本次请求的精确新上限；批准绑定用户、任务、工作区版本、源文件指纹和这些上限，不能批准“无限制”。执行过程中超过已批准上限、无法可靠预估、无法预留安全磁盘空间或平台无法保障资源隔离时停止并返回资源限制错误，可由 Agent 以另一个明确上限重新申请。

### 敏感文件

- 常见 `.env`、私钥、证书私钥、凭据和 Token 文件可显示存在，但默认不读取内容。
- 用户明确要求读取敏感内容时复用 `needs_approval` 形成一次性批准。
- `.env.example` 等示例文件按普通文本处理。
- 工具结果、日志和遥测必须脱敏 Token、密码及私钥正文。

敏感文件最小匹配集合为：`.env`、`.env.*`（排除 `.env.example`、`.env.sample`、`.env.template`）、`*.pem`、`*.key`、`*.p12`、`*.pfx`、`id_rsa`、`id_dsa`、`id_ecdsa`、`id_ed25519`、`credentials.json`、`service-account*.json`、`.npmrc`、`.pypirc`、`.netrc`、`.git-credentials` 和 kubeconfig。误判时用户可通过一次性敏感文件批准读取该精确文件，不提供目录级豁免。

上述规则同时适用于文件工具、搜索摘要、命令、Skill 和其子进程。未批准时，受控程序看到文件不存在或权限不足的稳定结果；批准仅把该精确文件加入一次执行的只读视图，不允许命令修改它，也不把正文写入批准状态。

### 命令与并发

- 命令默认超时 30 秒，允许请求的最高超时 10 分钟。
- 标准输出和标准错误各最多保留 1 MiB，超出后截断。
- 同一任务最多并发 4 个文件读取、2 个普通命令和 1 个写入/文档保存。
- 同一规范化文件路径的写入跨任务串行；提交前检查原文件指纹，冲突时拒绝静默覆盖。

跨任务写锁由单个可信本机 broker 按规范化平台文件身份集中持有，不依赖某个 Agent、Python worker 或 renderer 的进程内锁；broker 重启后依靠提交前版本校验继续防止静默覆盖。

命令 runner 必须用流式管道持续读取 stdout/stderr，只在内存中保留各 1 MiB，超出部分继续排空并计数，不得使用无界 `capture_output` 后置截断。超时、撤销、任务取消或输出管道故障时终止整个受控进程树并回收资源。

stdout/stderr 在进入模型、前端事件或普通日志前必须经过流式脱敏：把工作区真实根和 broker 临时根替换为相对/占位标识，过滤已识别的 Token、密码和私钥正文。批准卡片同样只展示脱敏命令；原始待执行载荷只短期保存在 broker 内存并绑定决定 ID，不能写入 Chat 状态或日志。

## API、状态与数据骨架

### 权限真源与可信执行链

- Core 继续作为用户身份、任务所有权、Work 模式、唯一工作区绑定、授权版本和撤销状态的业务真源。
- Chat/Agent runtime 是工具调用编排方；现有 Local Proxy 扩展为 Local 与 Desktop 共用的 loopback 文件/命令 broker，并使用已有可信宿主 token 向 Core 解析权限。Desktop 主进程继续只负责原生选择和最小桥接，不再复制一套文件/命令执行逻辑。浏览器 renderer、模型、子 Agent 和 Skill 都不是授权真源。
- 现有“验证后返回 501”的内部解析边界升级为能力解析接口。可信执行方请求至少携带 `conversation_id`、`execution_id`、`actor_type`（`main_agent`、`sub_agent` 或 `skill`）、`actor_id` 和 `operation_class`。
- 调用方必须通过项目已有的内部服务认证，同时传递可验证的当前用户身份；仅知道任务 ID 或能力 ID 不能取得权限。
- 成功解析只向 Local Proxy broker 返回不透明 `capability_id`、工作区 ID/版本、内部根目录信息和过期时间。算法工具只向 loopback broker 提交相对路径和当前执行身份；浏览器、Desktop renderer、模型、普通工具结果和公开 API 永不取得主机根目录或可复用内部凭据。
- 默认能力有效期 30 秒，只能用于绑定的运行实例、任务、actor 和单次操作类别，不可转让、不可重放；写入提交必须重新解析或换取新能力。
- 超过 30 秒的命令、文档转换或其他长操作每 5 秒重新确认任务与授权状态；分段读取在返回每个窗口前复核。撤销、任务取消或版本变化后最迟 5 秒取消相关进程树/转换并禁止继续返回内容或提交文件。
- broker 只监听受控 loopback，并同时校验运行实例凭据、用户会话、任务执行身份和 Core 短期能力；不得因请求来自 localhost 就信任。renderer 不能直接调用任意文件系统或进程 API。平台 broker 或 containment 不可用时安全失败。

### 文件工具契约

所有路径字段均为工作区相对路径；响应也只返回相对路径。服务端忽略或拒绝模型伪造的根目录、用户、任务、能力、批准和策略字段。

- `list_directory`：输入 `path`（默认 `.`）、`recursive`（默认 `false`）、`max_depth`（最大 5）、`page_size`（最大 200）和不透明 `cursor`；输出相对路径条目、类型、允许公开的元数据、`next_cursor` 与 `truncated`。
- `search_workspace`：输入 `path`（默认 `.`）、查询文本或 glob、`max_results`（默认 50、最大 200）和超时（默认 30 秒）；输出相对路径、匹配位置/安全摘要和 `truncated`，不得把敏感文件正文作为摘要返回。
- `read_text_file`：输入 `path`、起始行或不透明窗口游标、`line_limit`（默认 2,000、最大 4,000）；输出最多约 10 KiB 的文本、`next_cursor`、`eof` 和不透明 `version`。
- `create_directory`：输入 `path` 与 `parents`；目标已是目录时幂等成功，目标是文件或父路径类型冲突时返回冲突。
- `write_text_file`：输入 `path`、内容、`mode`（`create`、`overwrite`、`append`）和适用时的 `expected_version`。`create` 要求目标不存在；覆盖或追加已存在文件时必须提交最近读取/查询得到的版本，版本变化返回冲突。
- `replace_text`：输入 `path`、唯一旧文本、新文本和 `expected_version`；旧文本不存在或出现多次时拒绝歧义修改，版本变化返回冲突，成功后返回新版本。
- 文档 Skill 写回完整二进制结果时使用受控 staging/commit 接口，遵守相同相对目标、100 MiB、版本、原子提交和能力复核规则，不向 Skill 暴露内部临时路径。
- 写入响应只返回操作类型、相对路径、大小和新 `version`。`version` 是执行器根据文件身份、大小、修改时间和必要内容摘要生成的不透明值，调用方不能自行构造。
- 分页游标、读取游标、版本和能力均绑定任务与工作区版本；撤销、改绑、过期或跨任务使用返回稳定错误，不自动重新授权。

### 高风险批准与任务恢复契约

- 复用现有 `tool_limit_control` 协调器、Agent control 队列、Core 所有权校验端点、SSE 状态更新和前端 `ToolLimitCard` 的暂停/恢复链路；扩展本地命令与敏感文件的决定类型，不另建平行的前端轮询体系。
- `needs_approval` 创建 `pending_decision_id` 后真正暂停当前 Work 任务。前端只提交该 ID 与 `allow_once` 或 `deny`，不能提交替换后的命令、路径、用户或授权数据。
- 同一任务同一时间只展示并处理一个批准；主 Agent、子 Agent 和 Skill 并发产生的其余批准按到达顺序排队。排队项不计时；10 分钟有效期从服务端把该请求提升为当前 active 并发布 pending 事件时开始，以服务端单调时钟为准，不依赖浏览器是否实际渲染。
- 相同决定的相同动作重复提交是幂等的；不同动作、已消费、过期或非当前决定返回明确冲突/过期结果，不会再次执行命令。
- 页面刷新或 SSE 重连后，从受控 Chat 状态恢复当前 pending 决定和队列位置；运行时重启不恢复执行许可，旧决定统一失效并允许 Agent 重新申请。
- 拒绝通过既有 Agent control 队列返回结构化结果，恢复任务并允许寻找替代方案；永久禁止操作不创建 pending 决定，也没有允许动作。
- 批准状态只存放于本机短期运行状态及现有 Chat 状态缓存，不新增长期批准数据库表；记录命令/文件的脱敏展示、规范化摘要和绑定元数据，不保存 Secret、文件正文或可直接执行的未脱敏载荷。

### 数据库与迁移

- 当前数据库约束和默认值仅接受 `write_policy=ask_before_write`，因此本迭代迁移是必需项，不是可选项。
- 新增独立 Core dev up/down migration，不修改已存在的 migration；同步 PostgreSQL、SQLite 和 v0_3 aggregate 的最终 Schema。
- up migration 将策略允许值和默认值调整为最终 `allow` 语义，并把未发布环境中已有的 `ask_before_write` 本地工作区记录迁移为 `allow`。
- down migration 在恢复旧约束前把 `allow` 安全映射回 `ask_before_write`，保留授权、绑定和版本数据。
- SQLite 使用真实文件数据库验证建库、升级和回退；PostgreSQL 独立验证相同步骤，不能用任一方结果替代另一方。

### 错误语义权威性

- Core 错误目录是授权、能力、批准和 broker 边界错误码的唯一权威来源；OpenAPI、生成客户端、算法工具结果和前端文案从同一语义映射，不各自发明同义错误码。
- Agent 工具层以结构化失败返回稳定 code、`needs_approval` 状态和安全提示；原始系统错误只进入受控脱敏服务端日志。
- 批准完成后恢复原工具调用时使用原 `execution_id` 和一次性决定，不通过模型重新拼接命令来模拟恢复。

## 文档处理与路径脱敏

- PDF、Office、图片等既有处理服务只能接收 broker 已验证并暂存的输入，或接收可由可信宿主兑换的短期能力；公开接口不得接受任意主机绝对源路径或输出路径。
- Office 转换服务现有的绝对 `source`/`target` 日志和原始 LibreOffice 错误输出必须改为工作区相对标识、request ID 与稳定脱敏错误；stdout/stderr、内部临时目录和异常正文不得返回前端。
- 转换结果先写入受控 staging，再通过文件 broker 提交到已批准的相对目标；服务内部为了提交结果进行的移动仅限同一受控 staging/目标流程，不构成对 Agent 暴露的移动能力。
- 文档处理失败、超时、取消或撤销时清理专用临时资源且不得覆盖原文件；清理动作只能作用于该次执行器创建并持有的 staging 对象。

| `LOCAL_EXECUTION_UNAVAILABLE` | `2002347` | 503 | 当前平台缺少可验证 broker、文件句柄边界或 containment |
| `LOCAL_RESOURCE_APPROVAL_REQUIRED` | `2002348` | 428 | 压缩/文档处理请求超过默认预算，等待用户批准精确新上限 |

对外错误不得包含原始异常、内部绝对路径、命令环境、堆栈或敏感内容。

## 非功能要求

- 安全失败：身份、任务、授权、路径、操作或命令策略任一不明确即拒绝。
- 撤销及时性：授权撤销后不得出现新的文件访问或提交；受控运行命令最迟 5 秒终止进程树。
- 原子性：普通文件覆盖采用安全临时文件替换；冲突不静默覆盖。
- 隐私：模型只接收完成任务所需的文件内容和相对路径，Secret 默认不读取。
- 可观测性：记录操作类型、相对路径摘要、任务和结果，不记录文件正文、完整主机路径或 Secret。
- 跨平台：Local 的 macOS/Linux 和 Desktop 的 macOS/Windows（以及仓库实际支持的其他本机组合）遵守同一权限语义；平台 containment 不可用时命令安全失败，不降级为无限制 Shell。
- 无新增生产依赖、服务或平行权限体系，除非后续 Review 明确批准。

## 不做项

- 不向 Agent 提供文件 API 形式的删除、移动或重命名工具；命令形式在目标位于工作区时直接允许，受控程序可在授权工作区内产生已说明的内部副作用。
- 不支持一个任务绑定多个工作区。
- 不支持 Chat、Cloud、Docker Compose 或 LAN 的本地工作区文件访问。
- 不把工作区加入知识库 file-watcher `allowedRoots`。
- 不允许模型直接获得或提交主机绝对路径。
- 不同步授权、批准记录或文件内容到其他设备。
- 不提供“永久允许所有危险命令”或任务级无限制 Shell。

## 完成标准

- 允许范围内的文件读取、创建、修改、Skill 和子 Agent 操作在 Local/Desktop Work 中正常工作。
- 越界、符号链接逃逸、撤销、Chat/Cloud/LAN、跨任务、永久禁止操作均安全失败。
- 普通命令直接执行，高风险命令能暂停、展示、一次性批准/拒绝/过期并安全恢复任务。
- 已确认的大小、搜索、并发、超时、输出和敏感文件限制可观察且有稳定错误。
- PostgreSQL/SQLite、Core/算法/前端/Local/Desktop 契约一致，相关回归和真实 Local/Desktop 人工闭环完成。
