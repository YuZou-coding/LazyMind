# Local/Desktop 任务工作区文件访问（第二迭代）验收清单草案

## 计划与门禁

- [ ] `spec.md`、`tasks.md`、`checklist.md` 已由用户批准。
- [ ] 用户提供的五张 UI 图片已按原始字节和 SHA-256 固化到计划 `assets/`，截图验收不依赖临时附件路径。
- [ ] 阶段一只增加测试和最小编译声明，生产文件能力仍返回 `LOCAL_FILE_ACCESS_NOT_ENABLED`。
- [ ] 阶段一测试报告完成并获得用户明确批准后才进入生产实现。

## 模式、部署与任务

- [ ] Local（`make local-up`）和 Desktop 的已绑定 Work 任务可获得文件能力。
- [ ] 快速问答/Chat 不注册或调用本地工作区文件工具。
- [ ] Cloud、Docker Compose 服务模式和 `make local-up-lan` 安全失败。
- [ ] 服务端不信任前端模式字段、模型参数或任意绝对路径。
- [ ] 无绑定、跨用户、跨任务、归档后无效执行身份和非 Work 调用安全失败。

## 任务级三档权限

- [ ] 权限模式保存在 Work 任务与工作区绑定上，允许值仅为 `always_ask`、`ask_as_needed`、`allow_all`。
- [ ] 新任务和升级前已有绑定默认 `ask_as_needed`；无工作区任务不创建权限记录。
- [ ] 同一授权绑定到多个任务时，各任务权限模式互不影响。
- [ ] `always_ask` 对文件创建/修改/删除/移动/重命名、联网和已连接应用逐次确认；读取和安全只读命令直接执行。
- [ ] `ask_as_needed` 仅对现有风险识别命中的命令、联网、敏感文件和资源扩容逐次确认。
- [ ] `allow_all` 跳过可批准操作，但不能放行越界、提权、系统破坏、权限/所有权修改及其他永久禁止项。
- [ ] 模式切换立即影响后续操作，但不会自动批准或消费切换前已处于 pending 的决定。
- [ ] 已有任务修改权限接口校验用户所有权、Work 类型、绑定存在性、版本和允许值。
- [ ] Core 能力解析与 Agent、子 Agent、Skill 上下文携带服务端确认的当前模式，模型参数不能覆盖。

## 授权与撤销

- [ ] 首次授权弹窗明确显示读取、创建和修改权限及精确文件夹范围。
- [ ] 授权策略为 `read_policy=allow`、`write_policy=allow`。
- [ ] 普通读取、创建和修改在授权后不再逐文件确认。
- [ ] 一个授权可被多个新 Work 任务复用，每个任务仍最多一个工作区。
- [ ] 撤销后主 Agent、子 Agent、Skill 和待执行操作立即不能新访问或提交；运行命令最迟 5 秒终止进程树。
- [ ] 重新授权同一路径不恢复旧任务。
- [ ] 工作区路径移动、删除、替换或不可访问后变为 `path_unavailable` 且不自动恢复。
- [ ] 工作区选择不修改 Desktop file-watcher `allowedRoots` 或知识库权限。

## 路径边界

- [ ] 模型、前端和公开 API 只提交工作区相对路径。
- [ ] 空字节、空路径、绝对路径、`..`、驱动器切换、UNC 越界和平台歧义被拒绝。
- [ ] 现有目标的符号链接逃逸被拒绝。
- [ ] 新文件通过最近存在父目录校验，父目录链接逃逸被拒绝。
- [ ] 授权后目录替换或同路径重建不能继承旧授权。
- [ ] 操作前和提交前均重新验证任务、授权、目录身份和规范化路径。
- [ ] Unix/macOS 从已验证根目录 descriptor 逐段、no-follow 打开；Windows 从已验证目录 Handle 打开并复核最终路径和卷。
- [ ] 在“校验后、打开或提交前”并发替换父目录或链接仍不能逃逸；平台缺少句柄级保证时安全失败。
- [ ] 完整主机路径不进入模型提示、普通聊天、遥测或普通日志。

## 允许的文件操作

- [ ] 列出目录、文件元数据、glob、文本搜索和分段读取正常工作。
- [ ] 创建目录及必要父目录正常工作。
- [ ] 创建、覆盖、追加和精确文本修改正常工作。
- [ ] 普通文本写入使用同目录临时文件和安全替换，失败不留下半文件。
- [ ] 原子替换只作为同一目标路径的内部提交手段，不向 Agent 暴露通用移动或重命名能力。
- [ ] PDF、Office、图片通过既有解析/Skill 处理，模型不直接接收原始二进制字节。
- [ ] Skill 生成的完整文档结果只能写回授权工作区。
- [ ] 文件在读取后被用户或其他任务修改时返回 `LOCAL_FILE_CONFLICT`，不静默覆盖。
- [ ] `create` 要求目标不存在；`overwrite`/`append` 已有文件要求最近的不透明版本，模型伪造版本无效。
- [ ] `replace_text` 要求唯一旧文本和最近版本；零次/多次匹配或版本变化均不修改文件。
- [ ] 分页/读取游标、文件版本及能力均绑定任务和授权版本，跨任务、撤销后或过期使用失败。

## Agent 可见文件能力与受控程序副作用

- [ ] Agent 文件 API 不提供删除文件/目录、递归/通配删除、移动或重命名，直接请求永久拒绝。
- [ ] `rm`、`mv`、`del`、`Move-Item` 等直接删除/移动命令在全部目标位于工作区内时直接执行，越界时永久拒绝且不显示批准按钮。
- [ ] 经策略允许的构建、格式化、测试和包管理程序可在授权工作区及专用临时目录内产生必要的删除/移动副作用。
- [ ] 内部删除/移动副作用不能越界，也不能扩大为权限、所有权、链接、挂载、设备或系统操作。
- [ ] 创建符号链接、硬链接、挂载和设备操作永久拒绝。
- [ ] 修改权限、所有者、ACL、扩展系统属性或系统配置永久拒绝。
- [ ] 不注册等价删除/移动工具；常见直接命令、解释器内联和包装意图被入口策略拒绝，但文档不把它表述成工作区内数据绝不会被受控程序删除的强安全保证。

## 主 Agent、子 Agent 与 Skill

- [ ] 主 Agent 使用当前任务的不透明工作区能力。
- [ ] 子 Agent 继承所属主任务精确工作区，不能扩大或跨任务复用。
- [ ] Skill 使用同一任务工作区边界，不能直接取得无约束主机权限。
- [ ] 内置 Skill 与第三方 Skill 权限一致；脚本只取得只读 Skill 源、受限工作区视图、受控依赖和专用临时目录。
- [ ] Skill 脚本环境采用 allowlist，Python、Node 和子进程不能访问工作区外或执行永久禁止操作。
- [ ] Skill sandbox 不可用时脚本执行安全失败，不回退到 DummySandbox 或无约束 `subprocess`；受控文件 API 仍可使用。
- [ ] 绑定 Work 任务不使用 Trusted Local 任意绝对路径行为。
- [ ] 模型构造 `root`、`cwd`、`allow_unsafe`、能力 ID 或其他内部字段不能绕过服务端。

## 普通与危险命令

- [ ] 正常只读、格式化、测试、构建和文档处理命令可在工作区执行。
- [ ] 沿用现有危险 token、phrase 和 Shell 重定向检测逻辑。
- [ ] 普通检查命令解析为结构化 argv 并以 `shell=false` 执行，不把模型字符串直接交给 `shell=True`。
- [ ] 普通命令固定在授权工作区，环境采用 allowlist，并限制子进程；模型不能覆盖 HOME、凭据、代理、动态库或运行时搜索路径。
- [ ] `.git/**` 等版本控制内部目录在命令/Skill 视图中只读；格式化、构建、测试或包管理的内部副作用也不能修改它们。
- [ ] 只读 Git 查询禁用 optional locks、hook、pager 和外部 helper，不因刷新索引写入 `.git/**` 或启动未受控程序。
- [ ] 已识别的项目格式化、测试和构建可在 containment 中直接执行；任意解释器内联代码、包管理、网络及现有危险逻辑命中的命令进入逐次批准。
- [ ] 可合理使用的包管理、网络下载和重定向等高风险命令返回 `needs_approval`。
- [ ] 工作区范围内的删除、移动和重命名命令不逐次确认；越界删除/移动/重命名，以及提权、权限修改、磁盘/挂载、关机、进程终止、Git 破坏性清理/硬重置、全局配置和其他越界命令永久拒绝。
- [ ] 永久禁止项没有“允许”按钮，用户和模型均不能通过 `allow_unsafe` 放行。
- [ ] 命令不能启动脱离任务生命周期的后台常驻进程。
- [ ] 超时、撤销或任务取消时，只终止该次受控命令创建的进程树，不影响无关进程。
- [ ] macOS、Linux 与 Windows runner 在系统调用层阻止工作区外访问、链接、改权限、提权和进程逃逸；删除/移动副作用只能落在授权工作区或专用临时目录，字符串黑名单不是唯一越界边界。
- [ ] containment 不可用时命令和 Skill 脚本安全失败，测试、构建或文档处理不降级到主机 Shell。

## 高风险批准闭环

- [ ] `needs_approval` 会暂停当前 Work 任务并生成一次性批准请求。
- [ ] 批准复用现有 `tool_limit_control`、Agent control、Core 所有权校验、SSE 和 `ToolLimitCard` 链路，不存在可绕过的平行决定入口。
- [ ] 确认卡片显示安全命令文本、工作区、相对 cwd、危险原因和拒绝/允许按钮。
- [ ] 批准绑定用户、任务、工作区 ID/版本、规范化命令和相对 cwd。
- [ ] 批准有效期为 10 分钟，使用一次后立即失效。
- [ ] 命令、参数、cwd、任务、用户或授权版本变化后原批准无效。
- [ ] 用户拒绝后返回结构化结果，Agent 可继续寻找替代方案。
- [ ] 授权撤销、任务结束和运行时重启使未消费批准安全失效。
- [ ] 批准状态不保存 Secret 或未经脱敏的敏感命令内容。
- [ ] 批准卡片只展示脱敏命令，原始载荷仅短期保存在 broker 内存并绑定决定 ID，不写入 Chat 状态或日志。
- [ ] 同一任务同时只有一个 active 决定，其余主 Agent/子 Agent/Skill 请求按 FIFO 排队且排队期间不计时；10 分钟从服务端提升为 active 并发布 pending 事件时起算。
- [ ] 相同动作重复提交幂等；冲突动作、已消费或过期决定不会再次执行原命令。
- [ ] 页面刷新或 SSE 重连恢复当前 pending 状态；运行时重启不恢复旧许可，但 Agent 可重新申请。
- [ ] 批准后以原 `execution_id` 和原始受控载荷恢复，不要求模型重新生成命令。
- [ ] 决定端点的数据库、队列或投递失败只返回稳定脱敏错误，不包含原始异常或内部细节。

## 资源限制

- [ ] 单次目录列表最多 200 项，默认递归深度 5。
- [ ] 搜索默认最多 50 条、最高 200 条，默认超时 30 秒。
- [ ] 默认搜索准确忽略 `.git/.hg/.svn`、`node_modules`、`.venv/venv`、`__pycache__/.cache`、`dist/build/out/target/coverage` 集合。
- [ ] 文本源和修改后文本最大 20 MiB。
- [ ] 单次文本窗口最多约 10 KiB，默认 2,000 行、最高 4,000 行。
- [ ] 单次文本写入最大 20 MiB。
- [ ] PDF、Office、图片输入和单个生成文件最大 100 MiB。
- [ ] Office/压缩容器默认最多 10,000 个条目、解包总量 500 MiB、单条目 100 MiB，且不自动递归解包嵌套压缩包。
- [ ] 压缩条目的绝对路径、`..`、符号/硬链接、设备和跨卷目标永久拒绝，不能通过批准放行。
- [ ] 超过默认解包预算时，在解包前通过 `needs_approval` 展示源文件相对路径/指纹及本次精确新上限；不存在“无限制”批准。
- [ ] 批准绑定用户、任务、工作区版本、源文件指纹和精确预算；文件变化、过期、消费或实际再次超限均停止处理。
- [ ] 无法可靠估算或预留安全磁盘空间时，即使用户批准也返回资源限制错误，不以耗尽主机资源为代价继续。
- [ ] 命令默认超时 30 秒、最高 10 分钟。
- [ ] stdout/stderr 用流式读取各最多在内存保留 1 MiB并标记截断，超出内容继续排空且不会因无界 `capture_output` 耗尽内存。
- [ ] stdout/stderr 进入模型、前端或普通日志前将工作区/临时绝对路径替换为相对/占位标识，并脱敏已识别 Secret。
- [ ] 同一任务最多并发 4 个读取、2 个命令和 1 个写入/保存。
- [ ] 同一规范化文件路径跨任务写入串行。
- [ ] 跨任务写锁由可信本机 broker 集中持有，不依赖 Agent/worker/renderer 的进程内锁；broker 重启后版本校验仍阻止静默覆盖。

## 敏感文件

- [ ] 常见 `.env`、私钥、凭据和 Token 文件默认只显示存在，不读取正文。
- [ ] 用户明确读取敏感文件时生成一次性 `needs_approval`。
- [ ] `.env.example` 等示例文件按普通文本处理。
- [ ] 敏感文件至少匹配 `.env`/非示例 `.env.*`、私钥与密钥容器、SSH 私钥、credentials/service-account、npm/pypi/netrc/git 凭据和 kubeconfig。
- [ ] 一次性敏感文件批准只适用于显示的精确文件，不提供目录级豁免。
- [ ] 工具结果、错误、日志和遥测脱敏密码、Token 和私钥正文。
- [ ] 未批准敏感文件在文件工具、搜索摘要、命令、Skill 及子进程中均不可读；一次批准只把精确文件加入该次执行的只读视图。
- [ ] 同一命令同时涉及网络、包管理和敏感文件时，一个卡片逐项显示全部原因，批准不扩大到未列出的文件或风险。

## 错误、契约与数据

- [ ] `2002332 LOCAL_FILE_PATH_FORBIDDEN` 用于路径越界和受保护路径。
- [ ] `2002333 LOCAL_FILE_OPERATION_FORBIDDEN` 用于未授权操作。
- [ ] `2002334 LOCAL_FILE_NOT_FOUND` 用于范围内目标不存在。
- [ ] `2002335 LOCAL_FILE_TYPE_UNSUPPORTED` 用于不支持的处理方式。
- [ ] `2002336 LOCAL_FILE_TOO_LARGE` 用于文件大小超限。
- [ ] `2002337 LOCAL_FILE_CONFLICT` 用于指纹或并发冲突。
- [ ] `2002338 LOCAL_COMMAND_APPROVAL_REQUIRED` 用于高风险命令等待确认。
- [ ] `2002339 LOCAL_APPROVAL_EXPIRED` 统一用于命令、敏感文件和资源扩容批准的过期、重放或上下文变化。
- [ ] `2002340 LOCAL_COMMAND_FORBIDDEN` 用于永久禁止命令。
- [ ] `2002341 LOCAL_FILE_RESOURCE_LIMIT` 用于数量、并发或运行资源超限。
- [ ] `2002342 LOCAL_FILE_IO_FAILED` 对外只返回脱敏提示。
- [ ] `2002343 LOCAL_SECRET_APPROVAL_REQUIRED` 用于敏感文件读取确认。
- [ ] `2002344 LOCAL_WORKSPACE_CAPABILITY_INVALID` 用于伪造、重放和上下文不匹配。
- [ ] `2002345 LOCAL_WORKSPACE_CAPABILITY_EXPIRED` 用于能力过期或授权版本变化。
- [ ] `2002346 LOCAL_COMMAND_TIMEOUT` 用于命令超时且进程树已终止。
- [ ] `2002347 LOCAL_EXECUTION_UNAVAILABLE` 用于安全 broker/句柄边界/containment 不可用。
- [ ] `2002348 LOCAL_RESOURCE_APPROVAL_REQUIRED` 用于压缩/文档处理超过默认预算并等待精确上限批准。
- [ ] OpenAPI、错误目录、实现、前端类型和测试一致。
- [ ] Core 错误目录是授权、能力、批准和 broker 错误的唯一语义来源，算法工具层和前端不定义冲突的同义错误。
- [ ] 内部能力解析请求校验服务身份、用户、`conversation_id`、`execution_id`、actor 和操作类别；仅知道任务或 capability ID 不能调用。
- [ ] 能力默认 30 秒、绑定运行实例/任务/actor/操作类别、不可转让和重放；写提交重新解析，长命令/转换每 5 秒复核授权，读取窗口返回前复核。
- [ ] `list_directory`、`search_workspace`、`read_text_file`、`create_directory`、`write_text_file`、`replace_text` 及文档 staging/commit 的字段、默认值、上限和响应已进入契约测试。
- [ ] 必须提供新的 up/down migration，并验证 PostgreSQL/SQLite 建库、升级、回退、数据保留和 aggregate 一致性。
- [ ] up migration 把默认值、约束和已有 `ask_before_write` 记录迁移为 `allow`；down 在恢复旧约束前映射回 `ask_before_write`，且不修改既有 migration。
- [ ] SQLite 表重建保留数据、主键、外键、唯一/普通索引、默认值和 CHECK 约束，完整 dev 路径与 aggregate 最终 Schema 一致。

## 文档处理与隐私

- [ ] PDF、Office 和图片处理只接收 broker 验证的输入或短期能力，不接受公开任意主机绝对源/目标路径。
- [ ] Office 转换日志不记录绝对 source/target，外部错误不包含 LibreOffice 原始 stdout/stderr、临时目录或异常正文。
- [ ] 生成结果经受控 staging/commit 写回相对目标，并遵守 100 MiB、版本冲突、原子提交和撤销复核。
- [ ] 转换失败、超时、取消或撤销不会覆盖原文件，仅清理该次执行器自己创建的 staging 资源。

## 前端与无障碍

- [ ] 第一迭代工作区选择、最近列表、绑定状态和撤销 UI 不回归。
- [ ] 新建 Work 默认显示“选择工作区”和“按需确认”，三个菜单/弹窗均收起且不默认选择目录。
- [ ] 工作区菜单按名称和路径实时筛选；有效授权直接切换，失效授权进入首次授权弹窗。
- [ ] 授权弹窗取消、关闭、遮罩和 `Esc` 均不授权、不切换；允许访问后授权并切换。
- [ ] 原生选择器取消保持当前选择；选中未授权目录仍需 LazyMind 明确授权。
- [ ] “不使用本地工作区”清除当前选择，权限入口禁用并恢复显示默认模式。
- [ ] 权限菜单包含“始终询问”“按需确认”“全部允许”；前两项立即切换，全部允许必须先确认。

## 数据库与跨平台

- [ ] SQLite 文件数据库验证授权、任务绑定、策略迁移和撤销状态；短期批准不新增数据库持久化。
- [ ] PostgreSQL 与 SQLite 迁移最终 Schema 和约束一致。
- [ ] macOS、Linux 与 Windows 路径、链接、大小写/驱动器和命令边界均有测试；无法在当前主机运行的真实平台验证被明确披露。
- [ ] 平台 containment 不可用时安全失败，不降级到无限制 Shell。
- [ ] Local/Desktop broker 不向 renderer 暴露主机根路径、内部能力或任意文件/进程 API。
- [ ] Local Proxy 是 Local/Desktop 共用的 loopback broker；Desktop main 仅保留原生选择/最小桥接，不存在两套不一致的执行授权逻辑。
- [ ] broker 同时校验运行实例凭据、用户会话、任务执行身份和 Core 短期能力，不能仅凭 localhost 来源调用。
- [ ] 不新增未经批准的生产依赖、服务或平行授权体系。

## 端到端

- [ ] Local：授权工作区 → Work 任务 → 读取 → 创建 → 修改 → 重启 → 状态保持。
- [ ] Desktop：完成相同文件闭环。
- [ ] 主 Agent、子 Agent 和 Skill 均在同一任务精确范围内完成允许操作。
- [ ] 正常命令直接执行，高风险命令可批准/拒绝/过期，永久禁止命令不能放行。
- [ ] 两个任务复用授权并发修改同一文件时不发生静默覆盖。
- [ ] 撤销后所有任务立即不能新访问或提交，运行命令最迟 5 秒终止。
- [ ] Chat、Cloud、LAN、恶意 renderer、模型伪造、越界、符号链接和敏感文件测试通过。
